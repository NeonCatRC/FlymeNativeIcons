# Как устроены «Значки Flyme»

Техническое описание: устройство сборки, механизм значков Flyme, генератор и набор ADW. Обзор и
использование — в [README](../README.md), сборка — в [build.md](build.md).

## Сборка

Команды, настройки, ключ подписи и инструменты разработчика — в [build.md](build.md). Здесь только
устройство самой сборки.

В репозитории нет кода и ресурсов Meizu: они попадают только в собранный APK из Калькулятора
телефона. Поэтому APK — только для личного использования, не публиковать.

Что делает `build.py`:

1. Декодирует Калькулятор 12.6 через apktool без smali → `<FI_WORK>/base` (кэш). Калькулятор — носитель UI-библиотеки Flyme 12 (flyme.support, com.meizu.common, androidx)
   и её ресурсов. R8 вшил id ресурсов в код библиотеки, поэтому таблица ресурсов базы сохраняется.
2. Подменяет манифест (`AndroidManifest.xml` в корне), добавляет наши ресурсы из `res/` (имена `fi_*`,
   values-файлы кладутся как `fi_<имя>.xml`), собирает apktool.
3. Генерирует `R.java` из собранного APK (`aapt2 dump resources`), компилирует `java/src` против
   `android-36.jar` + заглушек `java/stubs`, d8 → `classes3.dex`.
4. **Проверка ссылок**: все обращения к классам библиотеки ищутся в dex базы — R8 мог вырезать
   неиспользуемые методы. Сборка падает со списком отсутствующих.
5. zipalign + apksigner, ключ `<FI_KEYS>/flyme-icons.jks`.

Обфусцированные имена библиотеки (только то, что нужно; см. заглушки):
`AppCompatActivity.R()` = getSupportActionBar, `ActionBar.C(bool)` = setDisplayHomeAsUpEnabled,
`flyme.support.v7.app.a$a` = AlertDialog.Builder (`r` title, `s` view, `o` positive, `k` negative,
`q` single choice, `c` create, `e` context), `MzRecyclerView$m` = isEnabled/d для селектора.

## Интерфейс

Только родные виджеты 12.6: заголовок `mzNestedScrollActionBar` (большой → свёрнутый, фон шапки и
тулбара = `fd_sys_color_surface_default`, как в Заметках/Проводнике), карточки
`immersive_mz_preference_{head,middle,foot,alone}`, категории `mz_preference_category_immersive`,
`com.meizu.common.widget.Switch`, `MzSeekBar`, `MzButton` (нижняя панель закреплена в DecorView:
контент в nested-scroll выше экрана на диапазон сворачивания), диалоги Flyme.
Корень контента — `fitsSystemWindows="true"` (Flyme отдаёт отступ под свёрнутой шапкой так).

## Как применяется значок

Файлы `<pkg>_fg.png` / `<pkg>_bg.png` 432×432 в `/sdcard/Customize/.FlymeIcon/{OriginIcon,NightIcon}`
(нужен «доступ ко всем файлам») + рассылка `com.meizu.flyme.launcher.CHANGEICON`.
Ночной вариант пишется без `_bg` — лаунчер берёт ночной `background.png` темы (тёмный градиент).
Дневной по умолчанию — «Светлый фон» (тоже без `_bg`: белый `background.png` темы, знак в цвете
бренда); у сложных картинок и у светлых знаков с тёмной подложки дневной остаётся как в приложении.
`Icons.GEN_REV` — ревизия генератора: значки, нарисованные старой ревизией, перерисовываются при
следующей проверке.
Свои файлы помечаются sha1 в `files/registry.json`; чужие (Flyme) не перезаписываются без явного
выбора. Если запись прервалась на середине, уже записанные слои всё равно попадают в реестр (с
ревизией 0, чтобы их перерисовала следующая проверка), иначе они сошли бы за файлы Flyme.
Нечитаемый реестр не затирается: он переименовывается в `registry.json.bad`. Свой значок
приложение тоже кладёт в облачную папку (иначе «цвет значков» лаунчера на него не действует).

Восстановление: Flyme стирает облачные файлы пакета при каждой установке/обновлении. Без автозапуска
в «Управлении запуском» Flyme не пускает стороннее приложение в фон: широковещания отбрасываются
(«Background execution not allowed [3rd app]»), а задача JobScheduler не может поднять процесс
(«Binding to a service … requires a ifw permit[JOB/SYNC]»). Поэтому: проверка при каждом открытии
приложения; периодическая задача (15 мин) и приёмник установки — пока процесс жив или если разрешён
автозапуск. Восстановление ничего не удаляет, если пакет «не виден» (в фоне Flyme может скрывать
другие приложения); забытые записи чистятся только на переднем плане. Если Flyme положил свой файл
хотя бы в один слот, наши остальные слои этого пакета удаляются вместе с записью. «Убрать» на экране
значка заодно исключает приложение из автоматического оформления, иначе значок вернулся бы.

## Набор значков ADW

Настройки → «Собрать набор ADW»: все приложения (кроме живых Календаря и Часов) одним APK
`ru.neoncatrc.flymeicons.pack` в выбранном варианте (светлые или тёмные), так, как их рисует движок
Flyme: наши файлы, файлы Flyme или сгенерированные на лету.

- Шаблон собирает `build.py` (`pack/`): 512 слотов-заглушек `res/drawable-nodpi/fi_NNN.png`, `ic.png`,
  пустая активити с `org.adw.launcher.THEMES` и `com.gau.go.launcherex.theme`. Кладётся в
  `assets/pack_template.apk`. Приложения сверх 512 в набор не попадают; сколько их, пишет сообщение
  об установке.
- На телефоне (`PackBuilder`): PNG 256 px с маской лаунчера в слотах, `assets/appfilter.xml`
  (`ComponentInfo{pkg/класс}` → `fi_NNN`; лаунчер Flyme читает его, если нет `res/xml/appfilter`).
- `ApkWriter`: несжатые записи, выравнивание 4 байта, подпись APK Signature Scheme v2 ключом RSA из
  AndroidKeyStore (`fi_pack`, тот же при каждом экспорте). Записи пишутся в файл по мере отрисовки, в
  памяти только центральный каталог. Проверено `apksigner verify`.
- Установка через PackageInstaller (`REQUEST_INSTALL_PACKAGES`). Подтверждение на Flyme показывает
  собственный установщик (`FlymePackageInstallerActivity`: проверка на вирусы, для пакета не из
  магазина Meizu — предупреждение «Ещё установить»). Он ставит подготовленный APK сам и
  записывается установщиком набора, а нашу сессию оставляет committed, но незавершённой: статуса
  успеха не будет. Поэтому установка считается успешной по `PACKAGE_ADDED` набора, а после возврата
  из установщика (через 3 с) — по `lastUpdateTime` набора позже коммита, иначе — отменённой.
  Повисшая сессия отменяется, статусы старых сессий игнорируются по `EXTRA_SESSION_ID`. Всё это
  принимает `App`, а не экран настроек, так что результат доходит, даже если с экрана ушли во время
  сборки. Подтверждение, пришедшее в фоне, показывается на следующем экране приложения. Вариант и
  число значков сохраняются только после установки. Удаление — `PackageInstaller.uninstall`
  (`REQUEST_DELETE_PACKAGES`): `ACTION_DELETE` без этого разрешения на Android 16 молча не работает.
- У набора есть активити LAUNCHER: выбор стиля в лаунчере Flyme берёт превью набора из
  `LauncherApps.getActivityList()`. В списке приложений набор открывает настройки помощника, его
  значок (сетка 2×2 без полупрозрачных квадратов) помощник кладёт в `.FlymeIcon`, как свой.
- Картинки набора лаунчер не обрабатывает (`createIconBitmap(Bitmap)`: только подгонка размера), поэтому
  форма (`corner_size`) и «Content Size» учитываются при сборке; после их смены набор пересобирается.

Отладка: `am start -n ru.neoncatrc.flymeicons/.DevActivity --ez fi_pack_dump true [--ez night true]`
кладёт набор в `Android/data/.../files/pack.apk` (с проверкой подписи — `tools/devtool.py pack`).
`DevActivity` закрыта разрешением `android.permission.DUMP`: оно есть у adb shell, но не у обычных
приложений.

## Генератор (`Generator.java`)

Классификация фона (по видимой части 72dp из 108dp): нет / светлый / цветной / тёмный / сложный.

- Ночь, цветной фон: части переднего плана цвета фона удаляются; основной нейтральный тон знака
  (белый на тёмной подложке, чёрный на светлой) → цвет бренда (контраст ≥ 3 к #242424). Белый «чип»
  с вырезанным текстом остаётся белым.
- Ночь, светлый фон: знак как есть, мелкие замкнутые «дырки» заливаются исходным фоном, чёрные
  нейтральные части осветляются.
- Ночь, тёмный/сложный фон: знак как есть (или монохромный слой, если фон сложный).
- Ночью передний план приглушается (по умолчанию 15%, «Приглушение ночью» 0–40%): облачные ночные
  значки Flyme темнее дневных примерно на столько же (Claude: (211,108,75) → у Flyme (183,97,68)).
  Фон не трогается — это `background.png` темы.
- Сдвиг знака по горизонтали/вертикали: ±20% видимой стороны. Монохромный слой масштабируется
  относительно центра холста, поэтому задуманное автором смещение сохраняется.
- Обычные (не адаптивные) значки: плитка с однородным фоном разбирается на фон + знак, иначе значок
  вписывается в 0.56 слоя.

Отладка: `am start -S -n ru.neoncatrc.flymeicons/.DevActivity --ez fi_dump true` пишет превью
«сейчас/день/ночь» всех неоформленных значков в `Android/data/ru.neoncatrc.flymeicons/files/dump`
(обёртка с листами превью — `tools/devtool.py dump`).
